# Hey Muse Wake Word for Waveshare 1.75C Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add local “Hey Muse” wake detection to the Waveshare ESP32-S3-Touch-AMOLED-1.75C while retaining push-to-talk and the current Muse voice transport.

**Architecture:** A focused C++ detector module consumes the voice task's existing 16 kHz mono frames, computes microWakeWord features, and runs the embedded Hey Muse model with TFLite Micro. The voice task starts its existing recording/turn/reply path on detection and ends hands-free turns after trailing silence; detector setup failure leaves push-to-talk active.

**Tech Stack:** ESP-IDF 6.0.1; `espressif/esp-tflite-micro` 1.3.3~1; `espressif/esp-nn` 1.1.2; `esphome/esp-micro-speech-features` 1.2.3; existing Muse audio and Hatch voice APIs.

## Global Constraints

- Implement only for `CONFIG_MUSE_BOARD_WAVESHARE_S3_175C`.
- Keep the existing 16 kHz, 320-sample microphone capture as the only audio input path.
- Preserve push-to-talk and the existing 15-second recording limit.
- Suspend/reset detection while recording, playing replies, or sleeping on battery.
- Enable detection failure fallback to push-to-talk.
- Do not run tests or firmware builds for this change; inspect the diff and document that hardware validation remains outstanding.
